The system

What runs where, and how the pieces reach each other.

Fig. 01 · app/main.py · websocket/server.py · wake_listener.py

One backend process behind every way of asking

The desktop window, the Local Agent page and the Chrome extension talk to the backend over one WebSocket; the wake word lives inside the backend; REST calls use port 8000. The engine then drives Windows, Chrome and the model providers.

Fig. 02 · desktop/agent_desktop.pyw · app/main.py (lifespan)

From the desktop icon to “Listening for Emma”

The desktop app is also the backend's supervisor: it reuses a healthy, up-to-date agent, replaces an outdated one, or starts a new one, which then brings up its database, keys, Chrome attachment, WebSocket server and wake word.

One task, step by step

The LangGraph engine every task runs through, whichever window it came from.

Fig. 03 · agent/graph.py · agent/runner.py · agent/nodes/

One task, end to end

Recall reads memory, the planner writes steps, the actor does them, verify decides, a failure that is safe to repeat is replanned once, and learn writes memory back. Your rating is the last write.

Fig. 04 · websocket/server.py · _resolve_voice_scope

Which tools a task gets

Six rules, checked in order. A task that names a file on this laptop keeps the local tools even when it also says “open chrome”, because only local scope can do both halves.

Fig. 05 · agent/nodes/recall.py · state/reflection.py

Recall: four look-ups at once

Nothing here waits on anything else, so all four run together. Only when similar past tasks exist does the reflection model write a STRATEGY / AVOID note, and the planner waits for it at most 4 seconds.

Fig. 06 · agent/nodes/actor.py · agent/toolkit.py

The actor loop

Each turn the model either calls one tool or writes the final report. Guards stop runaway runs, and the duplicate-send guard makes sure a message goes to a person only once.

Fig. 07 · tools/runtime.py · run_sync · run_in_worker · on_main_loop

Where tool code runs

The main event loop serves your windows and must never block. Browser tools wait on Playwright without blocking it; local tools block (PowerShell, file scans), so their code stays on the worker thread.

Fig. 08 · agent/toolkit.py · output_indicates_failure

Did this step work?

Tools that always answer with the same success message are judged by that message alone, so your own words inside it (a WhatsApp message saying “can't”) never turn a success into a failure.

Fig. 09 · agent/nodes/verifier.py · agent/nodes/replanner.py

Verify, then maybe retry

The actor's own report is never trusted alone. A failed first attempt is replanned only if repeating it cannot duplicate an effect.

Fig. 10 · verifier/engine.py · verifier/rules/generic.py · verifier/llm_judge.py

How a browser task is checked

Concrete page rules first, a text judge on the page snapshot always, and a screenshot judge only when it could still change the answer.

How it learns

SQLite for facts and counts, ChromaDB for meaning, an LLM for the lesson, and you for the final word.

Fig. 11 · agent/nodes/learner.py · state/brain.py · state/semantic_memory.py

What happens after a task

Quick local writes finish before you see the result. The LLM lesson and the ChromaDB experience are written in the background, so learning never slows the answer.

Fig. 12 · state/semantic_memory.py · recall_sync

How similar tasks are found and ranked

The new instruction is turned into numbers once, offline, and compared with both past instructions and past lessons, so a lesson learned on one site can help on another.

Fig. 13 · state/brain.py · record_feedback

What 👍 and 👎 change

Your rating is stored on the task's experience and weighs every future recall of it. 👎 also asks what went wrong; that note is the first thing the agent is told to avoid next time.

Acting on this computer

PowerShell, the Win32 API and a vision model: no extra Python packages, and every action aimed at a confirmed window.

Fig. 14 · tools/local.py · open_app · tools/desktop.py · wait_until_app_ready

Opening an app

Launching is easy; knowing the app is ready is not. The agent watches the new window until the splash screen is gone before it types anything.

Fig. 15 · tools/local.py · send_keys · tools/desktop.py · OaskUI

Typing into an app

Keys are sent only to a window that is proven to be in front, and they go through SendInput, which reaches WebView2 apps like WhatsApp and types any language.

Fig. 16 · tools/desktop.py · see_window · click_window

Seeing and clicking inside an app

When there is no keyboard shortcut, the agent looks at the window, asks a vision model where things are as percentages, turns them into pixels, and clicks.

Fig. 17 · tools/local.py · _resolve_user_path · _known_folder

Your real Desktop, not a look-alike

On this PC, Windows keeps Desktop and Documents inside OneDrive, while an empty C:\Users\samar\Desktop still exists. Every file tool, upload and PowerShell script is pointed at the real folder.

Fig. 18 · tools/local.py · delete_path · _protected_paths · _recycle

Deleting, safely

Deletes always go to the Recycle Bin, and the folders your work lives in can never be deleted as a whole.

Fig. 19 · tools/local.py · _walk_files · find_files · search_in_files

Searching your files

Searches look at the files nearest the starting folder first and skip folders full of generated files, so “search my Desktop” covers what you mean before the time budget runs out.

Acting in Chrome

Playwright over the Chrome DevTools Protocol, in the agent's own Chrome window, next to yours.

Fig. 20 · browser/controller.py · connect

Getting a browser to work in

Chrome 136 and later refuse the debugging port on Chrome's normal profile folder, so the agent works in its own Chrome window, on its own profile. Your Chrome and all its profiles are never launched, copied or read.

Fig. 21 · tools/browser.py · click_element · browser/actions.py · _click

Clicking something on a page

A payment check comes first. Then the element is searched for in several ways within 6 seconds, and clicked in up to three ways.

Fig. 22 · tools/browser.py · upload_file · _attach_file

Attaching a file from this computer

The agent fills the page's file picker directly through Playwright, so the Windows file dialog never appears, and it asks you before any file leaves the computer.

Voice and models

Hands-free input, and how every model call survives free-tier limits.

Fig. 23 · app/wake_listener.py · app/voice.py

“Emma … done”

Vosk listens offline for two words only, with look-alike decoy words to absorb sounds that are almost “Emma”. Nothing is run until “done” is heard, and the instruction itself is transcribed once, accurately, by Whisper.

Fig. 24 · utils/litellm_patch.py · utils/key_pool.py · utils/llm.py

Every LLM call, on free keys

Several free Groq keys rotate, each resting separately per model after a rate limit; Google Gemini answers when all of them are resting or Groq is down.

The desktop app and safety

Starting, updating and stopping the agent, and the lines it never crosses.

Fig. 25 · desktop/agent_desktop.pyw · on_show_request · poll_health · quit

Opening the icon again, and stopping everything

The second launch only sends “show”. The running app decides what that means: update itself, start the agent, update the agent, or open a fresh chat.

Fig. 27 · app/tools/mail.py · scripts/setup_email.py

Reading and sending your email

The agent works in your own mailbox over IMAP and SMTP — not through the Gmail website — so every recipient, header and attachment is exact, and checked before anything leaves the computer.
